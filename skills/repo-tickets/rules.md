# repo-tickets — 일감 관리 규칙

JIRA 대신 저장소 안 md 파일로 일감을 관리한다. 상태는 디렉터리 위치가 말한다:
`docs/tickets/todo/ → doing/ → done/`.

기계적 동작(파일 생성·이동·로그 추가·검사)은 손으로 하지 말고 스크립트를 쓴다 —
사람·세션이 달라도 결과가 같아야 하기 때문이다. 스크립트는 이 파일 옆 `scripts/tickets.mjs` 이고,
**저장소 루트에서** 설치 경로로 실행한다 (Claude Code 설치 기준 `.claude/skills/repo-tickets/scripts/tickets.mjs`).

```sh
T=.claude/skills/repo-tickets/scripts/tickets.mjs   # 설치 위치에 맞게
node $T new task api-rate-limiting --priority 150 --title "API 레이트 리밋" --source "운영 중 429 미반환 발견"
node $T start task-api-rate-limiting
node $T log   task-api-rate-limiting "미들웨어 적용까지 완료, 다음은 테스트"
node $T done  task-api-rate-limiting
node $T lint
```

## 이름과 참조

- 파일명: `<우선순위>_<type>-<slug>.md`. 예: `150_task-api-rate-limiting.md`
  - **우선순위**는 3자리 숫자(000~999). **낮을수록 먼저 처리** — 오름차순 정렬이 곧 처리 순서다.
    바뀌면 리네임한다(`prio`). 같은 값이 여러 개여도 된다.
  - **type**은 `bug` 또는 `task` (에픽은 `epic`, 아래).
  - **slug**는 영문 소문자·숫자·하이픈(`[a-z0-9-]+`).
- **일감의 이름은 `<type>-<slug>`** 다 (예: `task-api-rate-limiting`). 저장소 전체에서 유일하다.
- **일감 참조는 어디서든 `[[<type>-<slug>]]` 로만 한다** — 문서·코드 주석·커밋 메시지·대화 전부.
  - 경로(`docs/tickets/todo/150_…`)로 참조하지 않는다. 일감은 상태가 바뀔 때마다 이동하므로 경로는 반드시 깨진다.
  - 번호(`150`, "150 티켓")로 부르지 않는다. 번호는 ID가 아니라 우선순위라서 바뀌고 중복된다.
    `[[task-api-rate-limiting]](150)` 처럼 번호를 덧붙이지도 않는다.
- **이름은 만든 뒤 바꾸지 않는다.** 취소·보류·범위 변경 같은 상태는 이름이 아니라 진행 로그에 쓴다.
  (`epic-foo` 를 `epic-foo-cancelled` 로 바꾸면 `[[epic-foo]]` 참조가 전부 깨진다.)

## 상태 이동

- **todo/**: 대기 중.
- **doing/**: 착수 시 파일명 그대로 이동(`start`). 진행 중인 작업의 가시성이 목적.
  - 착수하면 본문 끝 `---` 아래 `## 진행 로그` 에 **날짜별 로그**를 쌓는다(`log`).
  - **세션이 끊기기 전, doing 의 일감에는 반드시 "어디까지 했는지" 마지막 로그가 있어야 한다.**
    없으면 다음 세션이 이어받을 수 없다 — doing 이 잊혀진 WIP 무덤이 되는 것을 막는 규칙.
  - 작업이 중단·보류되면 사유를 로그에 남기고 todo/ 로 되돌린다(`stop`).
- **done/**: 완료 시 완료일을 붙여 `done/<YYYYMMDD>_<원래 파일명>` 으로 이동(`done`).
  - 옮기기 전 완료 조건 체크리스트를 채운다 (안 채워져 있으면 `done` 이 거부한다).
  - 취소도 done 으로 보낸다: `done <이름> --cancel "<사유>"` — 사유가 로그에 남고 체크리스트 검사는 생략된다.
- 작업 중 발견한 잠재 버그·후속 작업은 대화로만 보고하지 말고 todo 에 일감으로 남긴다(`new`).

## 쓰는 방식

일감은 **결정과 그 결정을 지탱하는 사실**만 담는다. 목적은 다음 세션이 같은 판단을 다시
하거나, 버린 선택지를 모르고 되고르는 것을 막는 것이다.

- 프론트매터에 `type`, `created`(생성일), `source`(발견 경위/근거 문서)를 기재한다.
- **선택지는 `(A)`/`(B)` 같은 임시 라벨이 아니라 이름으로 쓴다.** 라벨은 대화에서만 통하고
  문서·커밋 메시지는 혼자 읽혀야 한다. 버린 선택지는 **한 줄 + 왜 아닌지**로 충분하다.
- **결정이 바뀐 과정은 쓰지 않는다.** "처음엔 이렇게 적었으나 뒤집었다" 는 일감이 아니라
  작업자에 대한 기록이다. 바뀐 결론만 현재형으로 쓴다.
- 반대로 **코드 근거(파일:라인)와 재현 조건은 반드시 남긴다.** 그건 심의 과정이 아니라
  제약이고, 없으면 다음 사람이 처음부터 다시 찾는다.

## 에픽 (디렉터리형 일감)

**언제 에픽으로**: 서브태스크 3개 이상이거나 여러 세션에 걸치는 규모일 때만.
애매하면 일반 일감으로 시작했다가 커지면 에픽으로 승격한다 (남발 금지).

- **이름**: 일반 일감과 같은 규칙의 **디렉터리** — `<우선순위>_epic-<slug>/` (`new epic <slug>`).
- **README.md**: 에픽 디렉터리 안에 두고 배경/설계/**에픽 레벨 완료 기준**/진행 로그만 쓴다.
  **서브태스크 목록을 README 에 중복 작성하지 않는다** — `ls` 가 곧 목록이다.
- **서브태스크**: 에픽 디렉터리 안에 일반 일감과 같은 규칙으로 둔다 (`new task <slug> --epic <에픽 이름>`).
  이름은 저장소 전체에서 유일해야 한다.
- **서브태스크 상태는 제자리 리네임**: 디렉터리 이동 없이, 완료 시 파일명 앞에 `<YYYYMMDD>_` 를 붙인다.
  진행 로그는 각 서브태스크 본문 `---` 아래.
- **에픽 자체의 상태 = 디렉터리 위치**: 서브태스크를 `start` 하면 에픽이 todo 에 있을 경우 doing 으로 함께 옮겨진다.
  서브태스크 전부 완료(+README 의 에픽 완료 기준 충족) 후 `done <에픽 이름>` 으로 done 에 보낸다.

## 스크립트

`node .claude/skills/repo-tickets/scripts/tickets.mjs <명령>` — 저장소 루트에서 실행. git 저장소면 이동은 `git mv` 로 한다.

| 명령 | 하는 일 |
|---|---|
| `init` | `docs/tickets/{todo,doing,done}/` 생성 |
| `new <bug\|task\|epic> <slug> [--priority N] [--title T] [--source S] [--epic E]` | todo 에 일감 생성 (기본 우선순위 500) |
| `start <이름>` | todo → doing, 진행 로그에 "착수" |
| `log <이름> "<내용>"` | 진행 로그에 오늘 날짜로 한 줄 추가 |
| `stop <이름> "<사유>"` | 사유 로그 후 doing → todo |
| `done <이름> [--cancel "<사유>"]` | 체크리스트 확인 후 done/<오늘>_ 로 이동 |
| `prio <이름> <N>` | 우선순위 변경 (리네임) |
| `list [todo\|doing\|done]` | 상태별 목록 (처리 순서대로) |
| `lint [--dir <경로>]` | 규칙 검사. 오류가 있으면 종료 코드 1 |

`lint` 가 보는 것 (작업 트리만, git 히스토리는 보지 않음):

- 오류: 이름 형식 위반, 이름 중복, 존재하지 않는 `[[…]]` 참조, 경로로 된 일감 참조
  (`works|tickets` 아래 `todo|doing|done` 경로, 번호 포함). 경로 참조는 후보 이름을 함께 제시한다 —
  번호는 중복되므로 자동 치환하지 않는다. 후보를 보고 사람/AI 가 확정한다.
- 경고: 진행 로그 없는 doing 일감, 프론트매터 누락, `[[이름]](번호)` 처럼 번호를 덧붙인 참조,
  "080 티켓"·"일감 150" 처럼 자연어로 번호를 부른 참조,
  `[[ ]]` 없이 맨 이름으로 쓴 일감 이름, 옛 `docs/works` 폴더 언급.
